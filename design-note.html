Every header item has one job. The page reads as a sentence instead of a shelf.

01 / The shift

Completeness gave way to a workflow.

An information compilation optimises for completeness: every artifact gets similar weight, and the controls sit wherever they happen to live. The reader has to assemble their own workflow from the pieces. A feature optimises for task completion: it establishes modes, scope, state and actions, then arranges the interface around them.

The penalty page used to be a wall of three quick cards, a filter bar and a table. The VOD page was a header, a filter bar and a toolbar whose count, sort, view mode and add action all competed for attention. Both were readable. Neither told you what to do next.

The refine changed that grammar. Tabs created modes. The header became a control strip. The filter bar became a query surface, and presentation controls moved beside it instead of inside it. State became visible: the active tab, the active count tile, the copy button that names what it will copy.

03 / What changed

Seven moves that changed the page.

Modes replace panels

The penalty quick cards became 列表 / 統計 / 圖例. Only one mode is on screen, so the page asks what you came to do instead of asking you to scan everything. Statistics and legend stopped being modals competing with the list.

The header became a sentence

Title, count, modes and actions each got one job and one place. The count no longer lives in a list toolbar; the rule trigger no longer lives in the filter bar. The order itself carries meaning.

Query surface, not preview surface

Date, search and state narrow the data, so they share the colored panel. View mode and sort do not narrow anything — they change how the result is presented — so they sit outside the panel, on the same row. The visual separation encodes the semantic one.

The list toolbar lost its junk drawer

The count moved to the header, the add action moved to the title row, and the view and sort controls moved beside the filters. What remains is only what the list itself needs. On mobile, those controls degrade into one compact row instead of disappearing.

Statistics became a dashboard

數量 and 圖表 became symmetric section headings. The state count tiles are filters with state-colored active states; the copy button changes its label to match the selection; Ctrl+A sits with the list it applies to. The chart count stays with the chart's time range.

The latest penalty became a status line

As a thin bar, the newest penalty keeps its announcement without taking card-level weight. It reads as a status strip, so the eye moves on to the filter and the list instead of treating three cards as the page's content.

VOD and Penalty now share a grammar

Pills, eyebrow labels, accent buttons, state colors and filter-row geometry are the same on both pages. VOD does not need tabs yet, but it now speaks the same language: title, count, rule, add; query panel; presentation controls beside it. Moving between the pages feels like moving inside one product.

04 / Why it works

Six principles, applied.

Scope
Global filters, list presentation and page actions are different scopes. Giving each its own place removes the ambiguity of a toolbar that does a bit of everything.
Disclosure
Tabs hide secondary panels until they are relevant. Modals either became inline sections or were kept only for true drill-downs.
State
The active tab, the active count tile and the copy label all say what mode you are in and what will happen next. A compilation page has content; a feature has state.
Reduction
IDs and dates left the copy lists. Duplicate counts disappeared. The collapsed-panel machinery went away. Less chrome means the remaining controls read louder.
Degradation
Desktop puts the lens controls beside the query panel; mobile returns them to a compact toolbar. The structure survives the narrow width instead of being cropped.
Grammar
Shared shapes and shared semantics across VOD and Penalty make the site feel designed as a system, not assembled page by page.
05 / What I'd watch

The remaining friction is scope, not structure.

Open questions

The count's scope

共 N 筆懲罰 reflects the list filters, yet it is visible on 統計 and 圖例. On those tabs it can be misread as the total. Show it only on 列表, or label it as a list count.

Header density on mobile

For admins, title, count, tabs, rule and add can wrap into three rows. Icon-only actions below a breakpoint, or a single action cluster, would keep the header calm.

Two scopes on 統計

The list filters and the chart time range are independent. 數量 and 圖表 separate them, but one caption — “列表依上方篩選；圖表依時間範圍” — would remove the last ambiguity.

Mid-width tension

Between roughly 720 and 900px, a two-column filter bar plus the external view and sort controls can feel tight. A deliberate wrap point would help.

Don't add VOD tabs yet

VOD has one mode. Its header and filter row are enough. Tabs should appear only when a second genuine mode exists, otherwise they become decoration.

Bottom line

The refine changed the page's grammar, not just its skin.

It moved from “here is all the information” to “here is the task, its scope, its current state, and the next action.” The remaining issues are about count scope and responsive density — refinements of an already sound structure, not reasons to rethink it.
